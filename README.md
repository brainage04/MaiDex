# MaiDex

MaiDex is an Android companion app for **maimai DX** players. It combines an offline song/chart catalog with optional maimai DX NET account import, score analysis, unlock guides, and background progress tracking.

## Features

- Browse the bundled catalog of 1,831 songs and 7,294 charts.
- Search Japanese titles, romanisations, aliases, artists, and notes designers.
- Filter by category, difficulty, version, chart type, region, level/constant, BPM, and constant availability.
- Sort by level, title, rating, achievement, rank, DX score, release date, or BPM.
- Import DX NET profile data, scores, medals, recent play history, and judgment details for Japan or International accounts.
- Calculate chart ratings, total rating, rating milestones, achievement loss, and DX score loss.
- View score statistics, medal tables, best scores, Dan course guides, Chiho/Class Battle unlock guides, and chart details.
- Track circle history and play counts with a configurable daily background sync.

## Architecture

The app is a Kotlin/Jetpack Compose application with a small MVVM-style data flow:

- `MainActivity` hosts the Compose UI.
- `MaiDexApp` contains the catalog, chart detail, account, guide, statistics, and tracking screens.
- `MainViewModel` combines catalog, filter, score, profile, import, and tracking state into `CatalogUiState`.
- `CatalogRepository` installs and reads the bundled read-only catalog database.
- `UserDataRepository` stores imported scores, play details, profile data, and tracking snapshots locally.
- `MaimaiDxClient` uses OkHttp and Jsoup to read authenticated DX NET pages.
- `CircleTrackingWorker` schedules authenticated daily tracking through WorkManager.

There is no project-owned backend service. DX NET authentication is performed in an Android WebView, and imported account data is stored on the device. Profile images are cached only from allowlisted official DX NET hosts.

## Build and test

Use the Gradle wrapper from the repository root:

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

Instrumentation tests require a connected Android device or emulator:

```sh
./gradlew connectedDebugAndroidTest
```

Release builds enable code shrinking and use the `baselineprofile` module for startup performance profiling. Baseline profile generation requires a connected device.

## Catalog generation

The checked-in `app/src/main/assets/catalog.db` is generated by `scripts/build_catalog.py`. By default, the script reads the published catalog, the checked-in alias TSV, and the checked-in SilentBlue romanisation TSV, then writes the database back to `app/src/main/assets/catalog.db`.

```sh
python3 scripts/build_catalog.py
```

The generator uses `pykakasi` for generated romanisation. It records the catalog update time and upstream source URLs in the database metadata.

Primary catalog source:

- <https://dp4p6x0xfi5o9.cloudfront.net/maimai/data.json>

Enrichment sources are recorded in `scripts/build_catalog.py` and the generated database metadata.

## Data and privacy notes

- The catalog is bundled for offline browsing.
- Imported scores, play details, profile information, and tracking history are persisted locally.
- DX NET requests require an authenticated session and network connectivity.
- Removing imported account data clears local score, profile, tracking, and cached profile-asset data.
- The DX NET parser depends on the structure of the official HTML pages and may require updates if those pages change.

## CI direction

A top-level CI workflow should run on pushes and pull requests, install JDK 17 and Android SDK 36, then run the unit tests and debug build. Instrumentation tests and baseline-profile generation should be a separate device-backed job rather than a required host-only job.

The repository does not currently include a checked-in GitHub Actions workflow.
